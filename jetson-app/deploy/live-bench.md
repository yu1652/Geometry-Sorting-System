# 实机调试与比赛入口

在 Xavier NX 的 Ubuntu 图形桌面或 VNC 内运行。

```bash
cd ~/ylers-bench-5742bac/jetson-app
bash run_jetson.sh
```

默认打开真实设备入口。打开窗口本身不连接设备。顶部有串口、三摄连接与模型管理，底部可切换调试页和比赛页，并进入九点标定与升降。模型文件与本机已生成的引擎继续放在 `models/`。

## 先验收预览和通信

1. 电机和舵机驱动电源断开，确认串口权限包含 `dialout`。若上位机原先从旧桌面会话启动，该会话可能尚未获得新组权限，可在 VNC 桌面终端先执行 `newgrp dialout` 再启动程序。
2. 点击「连接三路相机」。默认使用已确认的物理端口，拼图左侧为识别区俯拍 USB 2.1，右侧为识别区侧视 USB 2.2，托盘定位为 USB 2.4。通过「相机设置」修改端口。初始请求 MJPG、640×480、15 FPS；帧率提示不被支持或未报告时使用驱动提供的采集节奏，日志记录报告值。MJPG 格式和实际 640×480 画幅仍会检查，三摄同时打开和实际协商结果仍需现场验收。
3. 选择 `/dev/ttyUSB0`，点击「连接串口」。等待 ESP32 复位、清除串口残留后，程序只发送 PING、版本和状态查询。看到「通信已验收」后继续。
4. 在识别区放一件物体，点击「手动识别（只显示）」。工作线程采集原始双摄图，按旧版中心裁剪、灰度／CLAHE／边缘通道生成输入，再调用当前形状引擎。原彩色图用于 HSV。手动识别不发送箱号或推料。

## 九点标定与升降

1. 打开「九点标定 / 升降」，选择「导入旧标定」。本地交付更新包中 `imports/xy_calibration.yaml` 是原工程的九点文件副本，不包含在公开仓库中。
2. 检查 P1–P9 的像素位置与机械毫米坐标，保存为 `data/live_calibration.json`。默认示例点不会自动成为有效实机标定，保存或修改后实测确认框会清空。标定仅在成功校验后加载。
   - 可先调整顶部画面中的辅助框：框内拖动平移，拖动四角缩放，框外按住拖动重新画框；也可用上方「框 X / 框 Y / 框宽 / 框高」输入或上下箭头调节。坐标按原始 640×480 画幅计算，预览留黑边不会改变坐标。
   - 点击「按框生成九点」，按三行三列生成 P1–P9 像素坐标。默认内缩 15%，可调 0–45%。生成只更新像素草稿，保留现有九点机械 X/Y；再逐点微调到标定板十字中心，最后保存。重新生成会覆盖当前像素草稿。
   - 点击「保存标定」会将九点坐标、辅助框的位置大小和内缩比例一起写入 `data/live_calibration.json`。再次打开窗口或重启程序会恢复，打开时不会重新生成九点或覆盖微调值。关闭前未保存的修改会丢弃。旧文件没有框配置时保留旧九点，框先采用默认值，重新调整并保存一次即可。辅助框仅生成像素点，不修改托盘检测 ROI；编辑框和点不会发送移动指令。标定窗口持续刷新当前托盘画面，方便对点。
3. 无原点限位时，先在驱动断电状态手动移到固定零点，清空工作范围。准备进行动作测试时恢复驱动供电，保持机构位置，然后点击「手动零点确认」。确认框会提示真实 RESET 的行为。等待设备 READY，界面进入手动 armed。
4. 逐点选择 P1–P9，调整机械 X/Y，点击「GOTO 选中点」。数值框支持上下箭头、鼠标滚轮和直接输入，像素坐标每步 1 像素，机械坐标每步 0.1mm，调节时同步选中对应点；修改数值仅更新草稿，GOTO 才请求移动，保存标定才写入文件。界面等待设备状态报告目标脉冲到位。STATUS 坐标按固件版本换算。Linux 配套固件 0.1.1 为 X=40、Y=40 脉冲/mm，旧版 0.1.0 为 X=40、Y=39。按住「下降对点」可查看对准情况，松开、关闭窗口或点击「抬起」会请求抬起，等待真实 PUSHER_UP 后结束 pending。
5. 完成实测并保存，勾选「九点标定已在实机逐点核对」。这项确认每次重新启动程序都需要重新检查，修改标定或相机端口会清空确认。
6. 点击「托盘定位（只显示）」，核对目标毫米坐标。当前定位 ROI 为 `(154,35,379,380)`，使用右侧接触边缘与 `(4,0)mm` 推料间隙。按用户确认的机械行程，X 为 `0–260mm`、Y 为 `0–230mm`（含上限）；输入、保存、旧标定导入、坐标转换、GOTO、自动推料与仿真共同使用 `motion_limits.py` 的范围。托盘尺寸仍是 160×160mm，和以手动零点为原点的机械坐标范围独立。加上推料间隙后的起点须在机械行程内，且至少比推料终止线多一个 X 轴步进脉冲。0.1.1 终止线为 X=40 mm，0.1.0 为 X=10 mm。旧位置补偿尚未整体移植，必须以现场九点和定位结果验收为准。

## 单件再到连续分拣

1. 新一轮开始前取出六箱内的物块，在停机确认后点击「清空本轮」。无需预设类别或箱号。首个有效“形状＋颜色”类别分到1号箱，第二个不同类别分到2号箱，依次至6号箱；相同形状但颜色不同算新类别。六箱绑定后已知类别仍投入对应箱，第七种新类别停机提示，本件不发送 SORT。形状或颜色不确定时不分配新箱。
2. 三路画面有效、串口验收通过、原点确认和标定实测确认后，点击「运行」。首次没有任何箱号绑定也可以开始。此时才发送 HOST_READY；等待设备确认后发送 START。原点确认本身只开放手动调试，不提前开放物理启动键。
3. 收到 PUSH? 后取新托盘图定位，发送毫米推料坐标；收到 SCAN 后先确保模型已经加载，再连续读取相机排除旧帧。自动识别每次至少读取四批三摄画面并等待 0.8 秒，以最后一批双摄图识别；中途继续更新预览。最多复核八次，相邻两次有效“形状＋颜色”相同才决定箱号、持久化预留并发送一次 SORT。未知颜色、类别或颜色变化会重置连续匹配；耗尽预算后停机，不分配箱号、不投箱。独立判空连续三次成立时改走下述重新推料流程。两次之间间隔至少 0.25 秒，通信与动作原有超时仍有效。收到真实 DONE 后才确认数量、在比赛页显示图片并写入 `data/live_results.jsonl`，重复或过期 DONE 不计数。手动识别仍使用同一识别器、预处理和颜色配置，排过四批新画面后识别，不占用箱号，也不发送 SORT。比赛页显示每箱自动类别及本轮数量，「本轮箱号」为只读查看。
4. 先验证一件的坐标、动作和箱号，再验证多件。模型管理会停机、断开设备，并打开独立离线验证窗口；模型更换后关闭该窗口，再重新连接设备与确认零点。

自动箱号、数量和待确认投箱记录保存在 `data/live_auto_bins.json`。Jetson/Linux 在预留返回成功前同步文件、发布目录和父目录，保存失败不会发送 SORT。正常停止、复位和软件重启保留本轮；「清空本轮」在设备空闲且操作员确认六箱已清空后重置，不改变相机和九点标定。设备未连接时无法确认实际停机，清空操作会要求先断开电机和舵机驱动供电，确认机构停止、六箱已清空后再确认。若发送 SORT 后尚未收到 DONE 就中断，会保留箱号预留并阻止直接续跑，以免把可能已有物块的箱子分给其他类别；核查并清空六箱后开始新一轮。记录损坏或写入失败会明确停机，不自动替换已有记录。

旧的手动 `live_bindings.json` 不再用于实机分箱，文件保持原样。首次升级请先清空六箱并点击「清空本轮」，再验收“同类重复／颜色不同／六类／第七类”流程。新的自动分配逻辑已经离线测试，机械投箱结果仍需现场验证。

停止、重启、通信故障、摄像头失败或动作超时会使原点失效，继续前需人工对零。正常关闭会等待真实 STOP 确认，超时会明确记录未确认停止。现有 ESP32 固件动作是阻塞式的，软件 STOP 可能等当前动作结束后才处理，现场需有断开执行器供电的手段。

「运行」「停止」「复位」「退出」位于两个页面共用的底部操作栏。「复位」先发送 STOP，收到真实停机确认后提示人工回到固定零点，操作员确认后才发送 RESET，且不会自动恢复运行。「退出」等待停止确认并异步释放相机和串口。

目前用户现场已确认三摄实时预览和串口握手。九点动作、托盘目标定位和整机自动分拣尚需逐项验收。

## 无物块时重新推料

YOLO 没检出目标不能证明识别区为空：它也可能漏检已到位的物块。程序分开显示「识别区有物块，但模型未识别到目标」「识别区为空，等待连续确认」「未识别到目标，无法确认是否有物块」。

1. 停止自动流程并等待真实停机／空闲确认；清空双摄识别区，移开手，保持接料机构、相机、光照处于正常识别位置。托盘上的待分拣物块可以保留。
2. 点击调试页「采集空识别区」，阅读并确认提示。工作线程不加载模型，等待至少 0.8 秒并排过四批新画面，再保存左右原始参考至 `data/recognition_empty.npz`。画面过暗、过曝、无纹理或保存失败会拒绝，不自动学习第一帧或把未识别物体当作空区。
3. 自动识别时，用本次实际双摄原始帧与记录的参考独立比较。两侧都低差异、连续三次判空且 YOLO 也未检出目标，才发送现有 `PUSH,WAIT`；固件已有 `STATUS,PUSH,WAIT → schedulePushRetry → PUSH?` 支持。主机等待真实回应或新的 `PUSH?`，再拍新托盘图定位，不直接重用上一件 XY。不发送 SORT，不开投箱机构，不生成 DONE，也不分箱或增加成功数。此功能无需新增固件指令。
4. 有物块而无有效类别／颜色继续复核，耗尽后停机。无参考、换相机端口、参考损坏、坏帧或显著全局光照变化标记未知，不据此补推。模型目标与空区对比冲突时也不投箱或补推。相机位置、光照或接料机构位置改变后，清空并重新采集参考。

背景对比阈值是保守的初始值，已测试黑白彩色物块、低对比纹理遮挡、噪声与光变；无法保证感知所有物块，现场必须分别验收空区补推及有物块漏识别时不补推。光照／反光变化导致未知时先核对原图与参考，不降低模型阈值冒充判空。每份样本保存当时使用的 `empty_reference.npz` 及其 SHA256，重新采集不会改写旧样本中的判断依据；导出包也附带当前参考。

## 自动与手动识别对照诊断

此次修复针对首次拍照发生在模型懒加载之前、空画面立即停机、以及相机空闲轮询等待导致缓冲积压。它不修改现有模型、类别顺序、颜色阈值或置信度阈值，不保证一个稳定的模型误判会自动纠正。

1. 更新后，在静止单件上先做一次「手动识别（只显示）」，核对类别与颜色；再按原有对零和标定步骤验证一件自动流程。
2. 自动复核日志显示每次形状、形状分数、颜色、颜色分数、有效像素数、覆膜来源、请求 token 和 MCU epoch。停止后点顶部「导出诊断」，提示文件位于 `data/diagnostic_exports/export_*.zip`。可在 VS Code 远程文件栏右键下载这个 ZIP，不需要手抄全部日志。
3. 诊断包包含 `live_runtime.log` 及最多三份轮换日志、最近二十份识别样本和明确列出的相机／标定／本轮箱号／识别配置，不包含模型权重。样本内有 `captures/` 的三摄原始帧、未经画框的 `pair_bgr.png`、实际送入检测器且去掉补边的 `features_bgr.png`、覆膜及框预览、`raw_output.npy` 和 `metadata.json`。元数据注明手动或自动、取图／推理完成的单调时间、类别顺序、实际识别配置及所加载引擎路径和 SHA256。时间仅记录软件读图和推理阶段，不是摄像头真实曝光时间。特征输入样本会注明 preprocessed，不将其冒充原始彩色图。
4. 日志最多每份 2MB、三份备份；样本最多二十份，导出包最多三份。文件只保存在本机。更早版本只在窗口显示的日志无法由新版本补回，因此需更新后复现一次再导出。

模型异常、相机失败和实际通信超时仍立即停止，不用重试掩盖设备故障。首次模型加载期间允许匹配当前 token/epoch 的任务暂停预览，但原有整阶段 30 秒超时不延长；八次是最大复核次数，慢速加载或推理可能先触发该超时。若复核得到稳定错误类别，需要用保存的实际输入和分数继续分析训练／预处理；若颜色仍未知，需要检查取色区域、覆膜和光照后再调整阈值。现场尚需核对从 SCAN 到物块稳定的时间，以及单件投箱和后续连续分拣。

## 表面覆膜实际参与识别

提供的 `surface_mask_fp16.engine` 存在时默认加载。它用青色特征半图训练，所以从 YOLO 输入中取未补边的左右 320×320 特征半图分别推理，不给它原彩色图，也不重复灰度化或提边。原彩色帧仍用于取色。

只有同侧单个 YOLO 目标与掩膜可明确关联时，才选择与框重叠最大的前景连通区域，裁到目标框内，保留内孔背景。有效掩膜参与收紧表面框（青色细框）与原图 HSV 取色，原 YOLO 绿色框仍显示。掩膜失败、无匹配、输入不兼容、多目标歧义等都有状态，不把矩形填充冒充掩膜；缺少可用掩膜时会在日志标明检测框取色。

调试结果显示「左覆膜 / 右覆膜」以及可见内孔候选数。内孔候选是掩膜拓扑检查，不是棱数或类别；没有可见封闭内孔不代表实心，多出来的孔也可能是分割错误。现有模型部分样本仍有漏孔和误孔，因此不凭孔数自动替换 YOLO 类别。先在手动识别下对比实际环件、实心件和颜色，再决定是否通过自动分拣验收。新增流程的板端耗时和效果待现场核对。

`legacy_vision.yaml` 中 `surface_mask.enabled: false` 可关闭本地默认掩膜加载作对照（重启生效）；已经激活的模型发布包优先，按它的预处理声明加载。特征训练包用 `surface_features320_v1`，原彩色训练包用 `surface_rgb320_v1`，不得只改名字而不核对训练输入。

## 图形桌面登录后自启

完成上述验收后，可为当前安装目录配置登录自启。

```bash
mkdir -p ~/.config/autostart
cp deploy/ylers-sorter.desktop ~/.config/autostart/
```

模板按当前 `/home/nvidia/ylers-bench-5742bac/jetson-app/` 目录配置，换安装路径时需同步修改 Exec。若已有旧自启条目，应先更新或停用旧条目，避免同时启动两套程序。要在通电后直接进入图形桌面，仍需在 Jetson 系统设置中确认用户自动登录。自启仅打开界面，运行仍需手动对零和现场确认。自启与自动登录尚待板端验收。
